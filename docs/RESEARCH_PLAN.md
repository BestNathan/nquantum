# nquantum 研究总纲

## 1. 项目使命

建立一个**可追溯、可检验、可比较**的量子计算知识和数据系统，持续回答：量子计算走到了哪一步？哪些问题已被实验证实？怎样衡量从物理演示到有实用价值的容错计算的距离？

**研究对象**：门模型为主；模拟与退火等路线作为独立类别记录，不混同于通用容错门模型。覆盖基础理论、器件、纠错、软件、算法、商业与产业链。

**非目标**：不做单一“量子算力排行榜”、不将比特数量当作性能、不把预期发布日期当作完成日期、不无证据判断量子计算会替代经典计算。

## 2. 六条研究主线

| 编号 | 主线 | 核心问题 | 输出 | 优先级 |
|---|---|---|---|---|
| R1 | [基础理论](../research/01-foundations.md) | 量子计算的数学模型和优势边界是什么？ | 概念地图、可执行线路示例 | P1 |
| R2 | [硬件架构](../research/02-hardware.md) | 技术路线如何规模化，受何种物理瓶颈约束？ | 技术比较卡、设备档案、指标时序 | P0 |
| R3 | [纠错与容错](../research/03-error-correction.md) | 逻辑错误率能否随码距改善，代价多少？ | QEC 证据矩阵、逻辑资源估算 | P0 |
| R4 | [算法应用](../research/04-algorithms.md) | 哪些任务有可复现的量子优势？ | 算法图谱、经典基线、成本评估 | P1 |
| R5 | [系统软件](../research/05-software-systems.md) | 编译、调度、控制与云服务能否支撑实际工作负载？ | 系统分层、平台和开发体验比较 | P1 |
| R6 | [产业生态](../research/06-industry.md) | 供应链、资本开支与商业模式是否形成闭环？ | 企业档案、产业关系、商业证据表 | P1 |

## 3. 跨方向研究问题

1. 物理比特增加是否伴随可用电路深度、保真度、校准稳定性同步改善？
2. 跨平台比较时，门集、拓扑、连通性、测试协议、后选择与误差缓解会产生多大偏差？
3. 实时纠错是否覆盖重复轮次、解码器延迟、逻辑操作以及可扩展性？“逻辑比特演示”和“容错通用计算”之间还有哪些缺口？
4. 量子-经典混合任务的端到端时间和成本如何计算？是否含排队、编译、测量与经典后处理？
5. 对具体应用，有无同预算、同准确度的强经典基线？
6. 企业公告、论文、第三方复现及商业合同之间，各自证明了什么、没有证明什么？

## 4. 研究产出契约

一条可发布结论至少包含：结论文本、实体（企业/设备/算法）、来源 URL、来源类型、发表/观测时间、实验或业务条件、可信度、验证状态、局限性。无法核实的数据留空，不以零代替缺失。

每月输出：路线进展（新增/更新/撤回证据）、关键实验、产业进展、下一步需要验证的问题；月报是未来功能，不在 V0 模拟为已发生。

## 5. 输出平台

- **GitHub**：研究报告、原始证据、数据与变更历史。
- **GitHub Pages**：面向阅读和比较的入口，首版展示研究地图、路线对比、指标释义、来源索引和路线图。
- **Issues / PRs**：问题 → 资料采集 → 复核 → 数据入库 → 页面呈现的流程。
- **实验环境（后续）**：保存代码、依赖、seed、模拟器/硬件后端和原始输出。
