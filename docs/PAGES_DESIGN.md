# nquantum Pages 信息架构与交互设计 V0

## 产品定位

一个**研究门户 + 技术对比工作台**，读者在 30 秒内找到值得跟踪的问题，在 3 分钟内看懂不同路线及量子指标的比较边界，并能追踪到原始证据。

## 一级导航

1. **总览 / Overview**：研究定位、已建立的研究轨道、方法论、研究工作流和下一步。
2. **技术路线 / Hardware**：超导、离子阱、中性原子、光量子、半导体自旋对照；展示潜在优势、主要挑战与研究入口，**不做主观排名**。
3. **指标体系 / Metrics**：按「规模与连接」「器件质量」「纠错与逻辑」「运行与经济性」分组；每个指标默认收起，点击展开公式、含义、解读限制、来源规范。
4. **研究专题 / Research**：六大研究方向、核心问题、文档直达链接。
5. **来源与证据 / Sources**：官方文档、论文与研究入口；展示可信等级及引用说明。
6. **计划 / Roadmap**：按 Phase 分组的可检验里程碑，区分完成/进行/规划。

## 视觉规范

- 深色科学/工程工作台：深墨背景、冷白文字、偏青/紫细节色；清晰的数字标识、低饱和边框。
- 正文阅读宽度控制在约 1200px；桌面固定左侧导航，移动端导航变为横向滚动。
- 视觉强度用于研究状态、重点信息，不将装饰性图形呈现为真实实验曲线。
- 只用本地字体栈和原生 HTML/CSS/JS，无外部资产、无需构建工具。
- 中文主语言、英文技术术语作为辅助标注。

## 交互规范

- Hash 路由，可直接分享某一研究页，如 `#hardware` / `#metrics`。
- Hardware 路线筛选与卡片；无数据时明确说明“方向性简介，非实测排名”。
- Metrics 支持按分组筛选及 `<details>` 展开释义；公式和限制可直接复制。
- Source 采用外链（新窗口、rel=noopener），研究文档跳转 GitHub。
- 移动端不隐藏关键风险声明；可键盘访问，提供焦点态，尊重 reduced motion。

## 页面与数据的契约

前端读取 `./data/research.json`；字段变更必须与文档同步。现阶段页面只显示确定性的分类、概念与来源链接，计数来自实际数据条目；不显示不存在的新闻、实时行情、模拟性能评分。

## 后续演进

V1：引入真实 observation 数据、来源细节页、跨设备同协议筛选、时间轴。V2：实验复现卡片、基准方法学对照、人工复核和更新流水线。不得在数据模型稳定前引入抓取定时任务。

## 部署

静态文件全部位于 `docs/`，由 `.github/workflows/pages.yml` 对 `docs/` 做语法与文件存在性校验，并上传为 Pages artifact。管理员需要**首次在 GitHub 仓库 Settings → Pages → Build and deployment → Source 中选择 GitHub Actions**。此后更新 `main` 分支上的 `docs/` 会触发部署，也可到 Actions → Publish nquantum Pages 手动运行。

如果部署失败：

1. `Configure Pages` 返回 `Get Pages site failed / Not Found`：检查 Pages Source 是否已设为 `GitHub Actions`；默认 `GITHUB_TOKEN` 不能自行首次开通 Pages。
2. `Validate and package` 失败：检查 `docs/index.html`、`docs/app.js`、`docs/styles.css`、`docs/data/research.json` 是否存在并通过语法校验。
3. `Deploy` 返回权限错误：检查工作流 `pages: write`、`id-token: write`、仓库 Actions 权限和 `github-pages` 环境保护设置。
4. workflow 完成但首页仍打不开：检查部署日志中的 `page_url`、公开页面地址及延迟；不要把构建通过视为站点已经可访问。
