# 研究方法论与证据规范

## 1. 证据层级

| 等级 | 来源 | 用法 |
|---|---|---|
| E1 | 原始论文及补充资料、开源实验数据、完整复现日志 | 可支持技术结论，仍需检查可复现性 |
| E2 | 官方硬件技术文档、API、校准数据、受审财务报告 | 支持限定版本/时间的事实 |
| E3 | 企业公告、演讲、技术博客、路线图 | 支持“谁在什么时间宣称什么”，不自动证明技术事实 |
| E4 | 媒体、第三方分析、评论 | 线索和交叉验证，原则上不能单独支撑关键数字 |

证据等级只反映来源属性，不等于绝对真伪。企业的同行评审论文可能是 E1，企业官网的预测仍是 E3。

## 2. 结论状态

- **verified**：原始材料核实，实验/定义/时间完整。
- **reported**：单一来源明确报道，但尚未独立核实。
- **planned**：路线图/目标/预期，尚非实现。
- **disputed**：存在相互冲突的可追溯证据。
- **superseded**：被新数据、撤稿、设备更新取代。

每条结论至少关联 `source_id`、`observed_at`（或明确缺失原因）、`conditions` 和 `limitations`，在页面展示来源及状态。

## 3. 量化指标的可比性

任何数值至少要记录：设备版本、qubit 子集/拓扑、原生门及 gate set、测量/benchmark 协议、采样量/置信区间、后选择与纠错/缓解策略、日期。不同条件不能默认同一坐标轴上比较。

| 指标 | 定义或计算方式 | 说明/风险 |
|---|---|---|
| Physical qubits | 在指定设备版本上声明的物理量子比特数 | 规模描述；不直接表示算力或可用比特数 |
| Gate infidelity | 若使用同一定义的 fidelity，则 `1 - F` | RB / XEB / process fidelity 等协议不可无条件混用 |
| Readout error | 按指定初态、读出矩阵或定义统计的误判比例 | 需区分平均值、最差值、态依赖和 SPAM |
| Coherence (T1/T2) | 特定实验得到的弛豫/退相干时间 | 单独看时间不能替代门操作性能 |
| Logical error rate | `逻辑错误事件数 / 已定义的逻辑操作或周期数`（仅在试验定义允许时） | 必须显示分母、code distance、解码器、是否后选择 |
| Physical / logical ratio | `使用的物理比特数 / 定义明确的逻辑比特数` | 只能在相同容错任务/目标下解释开销 |
| End-to-end cost | 编译 + 等待 + 运行 + 后处理的时间或实际账单费用 | 需记录工作负载与精度目标 |

上表仅给理解性定义，不代替特定论文采用的统计估计量；二项分布置信区间不应忽略。**没有共用协议就不给综合评分。**

## 4. 研究记录流程

发现来源 → 提取原文结论 → 保存 URL、时间和实验条件 → 证据分级 → 交叉核实 → 入结构化数据 → 页面呈现 → 定期复核。

每次变化通过 PR 解释：新增/更正/撤回了哪条结论；不得无说明覆盖历史观测值。

## 5. 数学与实验的界限

- 推导公式须注明适用模型和假设；经验拟合不写成普适定律。
- 模拟、真实 QPU 观测、供应商预测分别标记。
- 理论量子加速、特定 benchmark 优势与经济实用优势是三种不同陈述。
- 对商业信息，财务实际值、预测、合同公告与研究机构预测不得混算。

## 6. 数据为空时

使用 `null` 和缺失原因；前端展示“暂无可验证数据”。**不能用 0、猜测值或随机构造的演示值冒充真实指标。**
