# nquantum 项目路线图

> 阶段目标是可验收的交付，而非估测完成日期。

## Phase 0 · 研究框架 + Pages V0

- [x] README、六大研究方向与统一问题清单。
- [x] 指标/证据方法论、数据模型和来源规范。
- [x] GitHub Pages 信息架构与静态交互原型。
- [ ] 在 Settings → Pages 启用 main /docs 并验证公开 URL。
- [ ] 用至少 3 篇原始论文为研究问题建立第一轮证据记录。

**验收**：页面无虚构实测数值；所有指标展开均包含定义、含义与限制；移动端可阅读；导航和来源可点击。

## Phase 1 · 可信基础数据库

- [ ] 设备与研究实体 schema（稳定主键、版本信息）。
- [ ] Source、Claim、Observation 的 schema 和校验。
- [ ] 一条完整可复查的硬件公开 benchmark 采集链。
- [ ] 至少两种技术路线各有设备档案与可追溯资料。
- [ ] 论文与厂商公告的差异比对。
- [ ] 页面对“条件不可比”给出明确提示。

**验收**：每条数字均有来源 URL、时间、协议、条件；源数据变更能在 PR 中复核。

## Phase 2 · 量子纠错与实验

- [ ] 纠错论文专题及码距/逻辑错误率数据集。
- [ ] 复现至少一个可在模拟器运行的公开实验。
- [ ] 同任务经典基线；保存环境、seed、shots 和原始日志。
- [ ] 引入可比较的趋势图，仅限满足对照条件的数据。

**验收**：第三方按照记录重跑得到统计相容的结果；图表标注数据来源和比较口径。

## Phase 3 · 产业研究和持续更新

- [ ] 企业/产品/技术实体关系。
- [ ] 技术节点、公开可用性与商业信号分层。
- [ ] 周/月增量研究纪要与复核工作流。
- [ ] 自动发现候选资料，人工/规则确认后入库。

**验收**：支持追踪一条观点的更新链，不会将公司计划写成已交付。

## 推进纪律

优先解决研究可信度和真实使用场景；不为了增加图表和自动化而产生假数据或过度设计。
